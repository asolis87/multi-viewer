Release checklist — mview 0.4

This release ships document tabs and the review rail. Run every step below on a clean checkout of main before tagging; each step names the command, the expected output and who signs it off.

Request flow

A second mview call never starts a new server: it hands the file to the running one, which pushes it to the open page as a new tab.

Tag and publish

Once the matrix is green, tag from the release branch. The publish script refuses to run when the working tree is dirty or when the version in package.json does not match the tag.

git switch release/0.4 && git pull --ff-only && npm version 0.4.0 --no-git-tag-version && git commit -am "chore(release): 0.4.0" && git tag -s v0.4.0 -m "mview 0.4.0"
npm publish --access public --provenance   # requires the npm-publish environment in CI, never from a laptop
  • Announce in #mview-releases with the changelog link.
  • Close the milestone and move open issues to 0.5.
