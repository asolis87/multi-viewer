# mview — CLI viewer for Markdown, Mermaid and JSON

Local CLI (`mview`) that opens the browser on a 127.0.0.1 server and renders Markdown (with embedded Mermaid), Mermaid and JSON from a file, the clipboard or stdin. Node + TypeScript CLI, Svelte frontend bundled into the package. v0.1 MVP = S1–S8; anything else (tabs, YAML, daemon reuse) is out of scope.

## Specs

- **S1 — Formats.** User: "un viewer para markdown, mermaid, json para mi uso cotidiano". Render Markdown (GFM, syntax-highlighted code), Mermaid diagrams, and JSON.
- **S2 — Open files from the terminal.** User: "me gustaria poder abrir archivos desde la terminal". `mview <file>` starts a local server, opens the browser, and live-reloads when the file changes on disk. Live reload means the page refetches `/api/doc` on a `change` event (no full page reload); if the file is deleted or unreadable, the page shows the error message. A missing path exits 1 with `mview: file not found: <file>`; a path that is not a regular file (e.g. a directory) exits 1 with `mview: not a file: <file>`, before any server starts (T15). Live reload keeps working when the file is deleted and recreated, or replaced by a rename (atomic save, as vim and many editors do) (L15, T12).
- **S3 — Paste from the clipboard.** User: "o pegar desde el portapapeles". `mview --paste` renders the clipboard content; `cat x | mview` renders stdin; `mview` with no input opens an empty page with a paste area (Cmd/Ctrl+V). Input precedence: a file, then `--paste`, then piped stdin; a file together with `--paste` is an error; an empty clipboard is an error; empty or whitespace-only piped stdin opens the paste page with `source: "empty"` and is not an error (L9, c61cae0). If piped stdin has not ended after 1 second, stderr shows `mview: waiting for input on stdin (press Ctrl+D to finish, Ctrl+C to cancel)` once and the CLI keeps waiting; stdin that ends sooner prints nothing extra (T16). Content pasted in the page lives only in the browser: there is no POST endpoint, and it is lost on a page reload.
- **S4 — AI-generated diagrams.** User: "tambien visualizo diagramas que me genera la IA". Fenced ```` ```mermaid ```` blocks inside Markdown render as diagrams; raw pasted Mermaid is auto-detected. Type detection: extension first (`.md/.markdown`, `.mmd/.mermaid`, `.json`); for content without a known extension: a JSON **object or array** that parses → json; the first meaningful line (skipping blank lines, `%%` comments and `---` front-matter) starts with a Mermaid diagram keyword followed by whitespace, `;`, `:` or the end of the line (list in `src/shared/detect.ts`, including variants such as `classDiagram-v2`, `flowchart-elk`, `zenuml`, `radar-beta`, `treemap-beta` — T17) → mermaid; otherwise markdown.
- **S5 — CLI that opens the browser.** User: "me gustaria explorar la idea de CLI que abre el navegador". One server per invocation on a free port, closed with Ctrl+C.
- **S6 — Publishable later.** User: "para el alcance mas adelante me gustaria publicarlo". npm-installable package (publish name pending, see L4); works offline (no CDN); server binds 127.0.0.1 only; random per-run token required on every API request; Markdown HTML sanitized (DOMPurify); Mermaid `securityLevel: 'strict'`. Remote images are blocked (L13): the page CSP allows images only from `'self'`, `data:` and `blob:`. In Markdown, every image whose `src` (trimmed, compared case-insensitively) starts with `http:`, `https:` or `//` — from `![]()` syntax or raw HTML `<img>` — is replaced by a visible placeholder box that reads "Remote image blocked" and shows the image's alt text (if any) and its URL as plain text, so no request is made. `data:` images still render. Images inside Mermaid labels are blocked by the CSP only (no placeholder). Remote `srcset` values and remote `<picture><source>` elements are removed. The replacement runs in the existing DOMPurify `afterSanitizeAttributes` hook in `src/web/lib/markdown.ts` (after sanitizing; no new module). The CSP change only removes `https:` from the existing `img-src` in `src/cli/server.ts` (L9 finding 1); the rest of the CSP is unchanged. Local relative images (`./img.png`) are out of scope for this change: they resolve against the mview server and show as broken images (404).
- **S7 — Decisions.** User: "1. Svelte 2. mview esta bien 3. dejamos pestañas para despues". Svelte frontend; binary name `mview`; no tabs in v0.1.
- **S8 — Accepted MVP extras** (proposal accepted with S7; L6: "2. agregalos a S8", "3. sumalo a S8"):
  - JSON tree with collapse/expand. Search is a case-insensitive substring match on keys and on scalar values (strings, numbers, booleans and `null`); highlights matches and expands their ancestors. Copy path: the first segment has no leading dot; copying the root itself is not allowed; a root array starts with an index (`[0].a`); identifier keys (ASCII `[A-Za-z_$][\w$]*`) use `.key`; other keys use `["x.y"]`; array indices use `[3]` (e.g. `a.b[3].c`, `a["x.y"]`).
  - Mermaid diagrams (raw documents and fenced blocks) support zoom, pan and Export SVG.
  - Manual type selector (markdown/mermaid/json) overrides detection; the chosen type is kept across live reloads until the user changes it.
  - Theme: a compact theme control in the toolbar, next to the type selector, styled like the toolbar of `design/mview-viewer/02-workbench.html` (L11), with three options — System / Light / Dark. Default is System (follows `prefers-color-scheme`). The choice switches the whole UI, code highlighting and Mermaid diagrams immediately, without refetching the document. It is not remembered: every run starts on System (L11).

- **S10 — Non-blocking start for agents (`--detach`).** User (L23): "esto es un cli .. me gustaria que cualquier agente pueda usarlo". `mview --detach <file>` accepts a file only (L25, Z3): without a file, or together with `--paste`, it exits 2 with `mview: --detach needs a file` on stderr, like the other usage errors; piped stdin is not read. It validates the file exactly as S2 (same `file not found` / `not a file` errors, exit 1), then starts a background copy of mview on that file with `--auto-close` (S11), not tied to the terminal. The background copy prints the URL and opens the browser (unless `--no-open`) as it does today; the foreground process forwards its `mview: <url>` line to stdout and exits 0. `Press Ctrl+C to stop.` is not printed. If the background copy exits before printing its URL (for example `--port` already in use), the foreground process prints the background copy's error on stderr and exits 1, and nothing keeps running. After the foreground exits, the background copy writes nothing and does not fail because its output is gone. Live reload (S2) works the same in the background copy.
- **S11 — Automatic close (`--auto-close`).** User (L23): "1. si" (also available by hand in the foreground) and "2. me parece bien ambos" (10 s and 60 s). An open page is one connected `GET /api/events` stream with a valid token. Every page with a valid token keeps that stream open for its whole life, whatever the document `source` (`file`, `paste`, `stdin` or `empty`) and also after the user pastes into the page (L25, C1; today the frontend only opens it for files, `src/web/App.svelte:219`). With `--auto-close` the server stops and the process exits 0 when either: (a) no page is open for 10 seconds after the last open page disconnects — a page reload or a new tab within those 10 s keeps it running; or (b) no page has connected within 60 seconds of the server starting. With several tabs it stops only after the last one closes. In the foreground it prints `mview: no open pages, stopping` to stderr in both cases (a) and (b), and still prints `Press Ctrl+C to stop.` at start. The 10 s and 60 s are fixed for the CLI (no option); `startServer` takes them as parameters so tests can use milliseconds, and it reuses the existing set of open SSE clients in `src/cli/server.ts` (L25, Z1–Z2). Without `--detach` or `--auto-close`, S5 is unchanged: the server runs until Ctrl+C.
- **S12 — Agent skill.** User (L23): "me gustaria hacer un skill que se instale junto con la herramienta"; agents (L23): "gentle-shell/pi,claude code, codex". The package ships `skills/mview/SKILL.md` in the repository and inside the release tarball (`package.json` `files` includes `skills`; the CLI finds it relative to its own `dist/cli/` directory; a test checks that `npm pack` includes it). Frontmatter `name: mview` and a `description` that tells an agent when to use it. The skill tells an agent to:
  - use mview to show the human a Mermaid diagram, a JSON document longer than about 20 lines, or a long Markdown document, instead of only printing it in the chat;
  - write the content to a file with the right extension (`.md`, `.mmd` or `.json`) — under the OS temporary directory when it has no file yet — and not delete it while the page may be open (live reload reads it);
  - run `mview --detach <file>` (never with `--no-open`), then give the human the printed URL and say that it stops working if no page is opened within 60 seconds and that running the same command again opens a new one (L25, C2);
  - not use `--paste` (the clipboard belongs to the human), not expect to read the page back (only the human sees it), and expect remote images to be blocked (S6).
  It is never installed by a package install script. Commands (L25, Z4–Z5):
  - When the first argument is `skill`, it is a subcommand; `mview ./skill` opens a file named `skill`. An unknown or missing `skill` subcommand exits 2 with the usage message.
  - `mview skill print` writes the bundled `SKILL.md` to stdout and exits 0. It also covers custom locations: `mview skill print > <path>`.
  - `mview skill install --agent <pi|claude|codex>` installs it for exactly one agent. Targets: `pi` and `codex` → `~/.agents/skills/mview/SKILL.md` (one shared copy: Pi also reads `~/.agents/skills/`, so a separate Pi copy would list the skill twice — Q1, L24); `claude` → `~/.claude/skills/mview/SKILL.md`. `PI_CODING_AGENT_DIR` is not used. Missing directories are created.
  - Outcomes: no file yet → `mview: installed skill for <agent>: <path>`, exit 0. Same content already there → `mview: skill already up to date: <path>`, exit 0, nothing written (so installing for `codex` after `pi` reports this). Different content → `mview: <path> already exists with different content; use --force to replace it` on stderr, exit 1, nothing written; with `--force` it is replaced and prints `mview: replaced skill for <agent>: <path>`, exit 0. A write failure exits 1 with `mview: <reason>`.
  - A missing, repeated or unknown `--agent` exits 2 with `mview: choose --agent pi|claude|codex` on stderr, writing nothing.
  - `--help` and the README describe `--detach`, `--auto-close`, `skill print` and `skill install`.
- **S13 — CSV and TSV tables.** User (L34): "podemos hacer una feature para añadir soporte para csv?"; answers (L34): "Tabla + ordenar + buscar (recomendado)", "CSV y TSV, delimitador autodetectado", "Siempre es encabezado", "Sí, artboards nuevos (recomendado)"; (L35): "Parser propio en src/shared/csv.ts (recomendado)", "Tope de 5.000 filas (recomendado)", "Lista de columnas", "Sí, aplicalos tal cual".
  - **Type.** New document type `csv` (`DocType`/`DOC_TYPES` in `src/shared/detect.ts`, label "CSV" in the type labels, `Doc.type` in the contract) for comma-, semicolon- and tab-separated content. The delimiter is not part of `Doc`.
  - **One shared module.** `src/shared/csv.ts` (own code, no new dependency — Q3) exports `parseCsv(text, delimiter)` and `detectDelimiter(text, filename?)`. `detectType` (CLI and browser) and the CSV view both use it; nothing else splits CSV.
  - **Delimiter.** `.tsv` → tab, always. `.csv` and a manual `csv` choice → `;` if it qualifies, else `,`. Content without a known extension → the first delimiter that qualifies in the order tab, `;`, `,`. A delimiter *qualifies* when, parsing with it, the first 20 records (blank records skipped; records, not physical lines, so a quoted line break does not end one; detection reads at most those 20 records) all have the same number of fields and that number is at least 2; if the 20-record window ends inside an open quote, that delimiter does not qualify.
  - **Detection.** Extension first: `.csv`/`.tsv` → csv (S4's `.md/.mmd/.json` unchanged). Without a known extension: JSON object/array → json; Mermaid keyword → mermaid; *tabular* → csv; otherwise markdown. Content is tabular when it has at least 2 non-blank records, some delimiter qualifies, and none of those first 20 records' first line, after trimming, starts with `|`, `#` or `---` (front matter is not skipped here, unlike S4). A trailing empty line is ignored.
  - **Parsing (RFC 4180).** Fields may be wrapped in double quotes; inside quotes the delimiter and line breaks are literal and `""` is one `"`. An unclosed quote runs to the end of the text. A `"` inside an unquoted field is literal text. A UTF-8 BOM is ignored; `\r\n` and `\n` both end records. Blank lines between records are skipped. A trailing delimiter makes an empty last field.
  - **Header and ragged rows.** The first record is always the header. Rows shorter than the header get empty cells. Rows longer than the header add columns named `Column <n>` (1-based position, e.g. `Column 4` when the header has 3 cells); an empty header cell is also shown as `Column <n>`. Duplicate header names are kept as they are. Content that yields one column renders as one column; content with only a header shows the header and "No rows"; empty content shows "No rows".
  - **Table.** The header stays visible while scrolling. Cells are plain text (never HTML or Markdown), cut to one line with an ellipsis, with the full value on hover. Styling reuses the Markdown table colours and padding (`.md th/td`) and adds only the sticky header and the cell width cap.
  - **Sort.** Clicking a column header sorts by it: ascending, then descending, then back to file order; clicking another column starts that one at ascending and clears the previous sort. A cell is *empty* when it is blank after trimming; empty cells stay last in both directions. A column sorts numerically when it has at least one non-empty cell and every non-empty cell, trimmed, matches `^[+-]?(\d+(\.\d*)?|\.\d+)$`; otherwise it sorts as text with `Intl.Collator(undefined, { sensitivity: "base" })`. Sorting is stable: equal values keep file order.
  - **Search.** Reuses the JSON view's search pattern (search box, Clear, highlight via the existing `highlightParts`, moved to a neutral `src/web/lib/text.ts`) and the existing status override path for the count. The search text is trimmed; matching is a case-insensitive, locale-independent substring test on data cells only (not the header). An empty box shows every row. Rows are filtered first, then sorted.
  - **Large files: pages (L45–L46, replaces the Q4 5,000-row cap).** `<total>` is the number of data rows in the file and `<shown>` the number that match the search; numbers use the existing `formatCount` grouping (e.g. `74,920`). The shown rows, in their current sort order, are split into pages of 200 rows (`PAGE_SIZE`, one constant in `src/web/lib/csvTable.ts`); only the current page is drawn, so every row can be reached. A pager below the table shows `«` first, `‹` previous, `Rows <a>–<b> of <shown>` (e.g. `Rows 201–400 of 74,920`), `›` next and `»` last; buttons that cannot move are disabled; the pager is hidden when the shown rows fit on one page, including 0 rows. There are no keyboard shortcuts for changing page. The status bar keeps `<shown> of <total> rows`; the "showing the first 5,000" notice is removed. **The page follows the selection:** while a row is selected and shown, the current page is the one that holds it — after ↑/↓, a sort, a search or a live reload. Without a selected row: a search or sort change goes to page 1; otherwise (live reload) the page stays, clamped to the last page. The pager buttons scroll the table back to the top; a page change caused by the selection scrolls the selected row into view. The search updates on every keystroke (no delay, L45). Before timings are the L45 numbers; after T34, load, search, sort and page change are measured once on the same 100,000-row file and recorded in the Log.
  - **Outline.** The sidebar lists the column names; clicking one scrolls that column into view and highlights its header. For CSV documents the sidebar starts collapsed on wide screens and the toolbar's "Outline" button (always visible for CSV, shown pressed when open) opens and closes it with a slide/fade (L38); below 900 px it keeps working as the existing overlay drawer. Other document types keep today's sidebar behavior.
  - **Row inspector (L36–L37, chosen artboard).** Clicking a row selects it (accent background, left accent bar) and opens an inspector panel on the right (340 px; below 1100 px it opens from the bottom at 42vh) that lists every column of that row with its full value, empty cells shown as an italic "empty", including extra `Column <n>` cells, and "Row <n> of <total> in file order". ↑/↓ move the selection through all shown rows in their current order (the page follows, see "Large files"), and do nothing at the first or last shown row; `Esc` or the panel's × closes it and returns focus to the row; it also closes when search hides the selected row, a live reload removes it, or the pager buttons show a page without it; when it closes this way the row is no longer selected and focus stays where it is (search box or pager button); if the focused pager button becomes disabled, focus moves to an enabled pager button (L47–L48). Nothing is selected and the panel is closed when a document loads. The panel opens and closes with a slide/fade; with reduced motion it appears without animation.
  - **Integration.** The type selector is built from `DOC_TYPES` and the type labels (no hard-coded options) and gains `CSV`; choosing it parses the current content as CSV (delimiter rule above). The app chooses the view with an explicit branch per type (`json` no longer falls under a catch-all `else`). Live reload (S2), theme (S8), auto-close and detach (S10–S11) work the same for CSV.
  - **Docs and skill.** The README formats table and the agent skill (S12, bullet 2) list `.md`, `.mmd`, `.json`, `.csv` or `.tsv`; an agent may use mview to show the human a table longer than about 20 rows.
  - **Design.** Chosen artboard: `design/mview-csv/03-table-inspector.html` ("Table and inspector", L39), with the two comment changes of L37–L38; tokens from `design/system.md`. Artboard-only controls (the data/search switcher) are not product UI. The artboards follow the patterns above (Workbench toolbar, JSON-style search, status bar count) instead of inventing new ones.

  - **Auto-close by default (A).** Every server started by `mview` stops by itself under S11's rules (10 s after the last open page disconnects, 60 s if no page ever connected), and the foreground process exits 0 after printing `mview: no open pages, stopping` to stderr, freeing the terminal. This changes S5 and S11: `--auto-close` is still accepted and changes nothing; S10 (`--detach`) is unchanged. `--no-open` follows the same rule (60 s to connect).
  - **`--keep-open`.** A new option that restores today's behavior: the server runs until Ctrl+C. `--keep-open` together with `--auto-close` or `--detach` exits 2 with `mview: --keep-open cannot be used with --auto-close or --detach` on stderr, starting nothing. `Press Ctrl+C to stop.` is printed in the foreground with or without it.
  - **Forgotten tabs (B).** When a page has been hidden (`document.visibilityState === "hidden"`, e.g. minimized or in a background tab) for 30 minutes without interruption, it closes its `/api/events` stream; the document stays on screen. The server then counts it as closed, so with auto-close it stops 10 s after the last page goes. Showing the page again before 30 minutes cancels the countdown. When a page that disconnected this way is shown again, it tries to reconnect once: if the server still runs (`--keep-open`, or other tabs kept it alive), it reconnects, refetches the document and shows `Live · watching <name>` again; if not, the status bar shows `Stopped — run mview again for live reload` and the page stops retrying (instead of `Disconnected — retrying`). The 30 minutes are fixed (no option); the page takes them from one constant so tests can use a shorter value.
  - **Docs.** `--help`, the README and the agent skill (S12) describe the default auto-close, `--keep-open` and the 30-minute hidden-tab rule; the skill keeps using `mview --detach <file>`.
### Server contract (shared by CLI and frontend)

- `GET /` → frontend `index.html`; static assets under `/assets/*`. These carry no document data and do not require the token.
- Token delivery: the CLI prints and opens `/?t=<token>`; the frontend reads it from `location.search`. Without a token, or with an invalid one, the page shows "This page needs the link printed by mview".
- `GET /api/doc?t=<token>` → `Doc` = `{ name: string|null, type: "markdown"|"mermaid"|"json"|"csv", content: string, source: "file"|"paste"|"stdin"|"empty" }`; read failure → `500 { error: string }`.
- `GET /api/events?t=<token>` → SSE; emits `event: change` when the watched file changes. The token goes in the query string because `EventSource` cannot set headers.
- Only `/api/*` requires the token: missing/wrong → `403`. Every route accepts exactly `Host: 127.0.0.1:<port>` and `Host: localhost:<port>`, compared case-insensitively as HTTP requires (T14); any other value (including the host without a port, or `[::1]`) gets `403` (DNS-rebinding guard). Unknown path → `404`.
- Shared code lives in `src/shared/`: `detect.ts` (`detectType(content, filename?)`, `firstMeaningfulLine` — T13) and `doc.ts` (`Doc`, `DocSource`, empty doc). Both CLI and frontend import them; neither redefines them.
